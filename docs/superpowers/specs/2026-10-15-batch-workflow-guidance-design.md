# 批次流程引导设计

## 1. 目标与范围

为物流库存管理应用增加可持续显示的业务流程引导，使用户始终知道：

- 当前正在处理哪个批次；
- 已经完成哪些业务步骤；
- 当前可以执行哪些操作；
- 下一步应该进入哪个页面；
- 某项操作被限制时，缺少哪个前置条件。

流程进度按具体批次计算，不按全局单一流程计算。一个应用实例可以同时处理多个批次，每个批次有独立的进度和分支。

本功能支持以下业务路径：

```text
入库 -> 直接出库
入库 -> 内部调拨 -> 出库
出库 -> 退回 -> 再次出库
```

调拨可重复发生，退回后再次出库复用普通出库流程。

本功能不改变现有库存记账、型号和单据状态规则，不自动替用户创建或确认业务单据。

## 2. 现有业务模型约束

当前产品层级为：

```text
产品分类 -> 产品类型 -> 产品型号
```

入库只选择产品类型，不选择产品型号；出库和退回明细可以选择产品型号。库存仍按“批次 + 库位”计算，型号用于出库统计、退回匹配和历史快照。

单据状态为：

```text
Draft -> Confirmed -> Cancelled
```

草稿不影响库存，确认产生库存流水，取消通过反向流水恢复库存或在存在后续依赖时拒绝取消。

## 3. 用户体验原则

### 3.1 始终显示

流程编号、当前批次、当前状态和下一步建议在主窗口和相关业务页持续显示。用户切换页面时保留当前批次选择。

### 3.2 提示并限制

历史记录和后续页面仍可打开查看，但当某项业务的前置条件未满足时：

- 新建或确认操作显示缺少的前置步骤；
- 相关操作按钮禁用或在点击时给出阻断提示；
- 提供“去完成”入口跳转到前置页面；
- 不阻止用户查询历史单据。

### 3.3 真实数据决定进度

打开页面不代表完成步骤，保存草稿不代表完成步骤。只有真实单据状态和库存流水满足条件，步骤才标记为完成。

流程状态从现有数据库实时计算，不新增需要用户手工维护的“当前步骤”字段。

## 4. 批次流程步骤

主流程显示六个编号步骤：

```text
01 基础资料
02 入库
03 库存安排
04 出库
05 退回处理
06 再次出库 / 流程结束
```

步骤状态统一使用：

- `未开始`：前置条件未满足且没有对应业务记录；
- `进行中`：存在草稿或存在尚未处理完的业务；
- `已完成`：该步骤的完成条件已满足；
- `不适用`：该分支没有发生；
- `需处理`：存在可以继续处理的库存、草稿或可退数量。

### 4.1 基础资料

完成条件：

- 批次关联的产品类型存在且启用；
- 产品类型所属分类存在且启用；
- 入库初始库位存在、启用且计入库存；
- 出库型号存在、启用且属于该批次的产品类型。

基础资料不完整时，入库确认或后续单据确认失败，并显示具体缺少字段和“去基础资料”入口。

### 4.2 入库

状态判断：

- 没有入库记录：`未开始`；
- 存在入库草稿：`进行中`，下一步为编辑并确认入库；
- 入库已确认：`已完成`；
- 入库已取消：`需处理`，建议重新创建入库草稿。

入库确认后在初始库存库位生成正数流水，批次获得可用库存。

### 4.3 库存安排

库存安排是调拨和直接出库的分支步骤，不强制要求发生调拨。

- 批次已确认入库且来源库存库位有库存时，可直接出库；
- 创建调拨草稿后显示为`进行中`，提示先确认或删除草稿；
- 调拨确认后显示调拨结果和当前库位分布；
- 没有发生调拨且批次直接进入出库时，调拨分支标记为`不适用`；
- 调拨可以重复发生，每次确认前检查来源库位批次库存。

调拨确认不改变批次总剩余，只生成来源库位负数和目的库位正数流水。

### 4.4 出库

当任意计入库存的库位存在已确认批次库存时，出库步骤为`需处理`或`进行中`，提示进入出库管理。

确认出库时：

- 检查来源库位库存是否足够；
- 检查批次已确认入库；
- 检查型号是否启用且属于批次产品类型；
- 同一批次在本单据中的数量合计不得超过来源库存；
- 保存批次、分类、产品类型和型号快照；
- 从来源库存库位生成负数流水。

库存仍大于零时继续提示可出库；库存为零且有历史出库时进入可退回状态。

### 4.5 退回处理

退回是出库后的可选分支。

当外部地点存在已确认出库并且某批次、型号仍有可退数量时，退回步骤为`需处理`。

确认退回时：

- 来源必须是外部地点；
- 目的地必须是启用且计入库存的库位；
- 退回批次必须来自历史出库；
- 型号必须与原出库型号匹配；
- 退回数量不得超过可退数量。

退回确认在目标库存库位生成正数流水，之后可继续进入普通出库流程。

### 4.6 再次出库 / 流程结束

退回产生的库存使用普通出库页面再次处理，可以选择原型号或符合业务规则的其他启用型号。

批次达到以下条件时显示`已完成`：

- 当前库存为零；
- 没有未确认草稿；
- 没有需要先处理的退回或取消依赖。

批次仍有库存时显示剩余数量和可执行的下一步。零库存历史批次仍保留批次追踪和完整时间线。

## 5. 流程状态数据对象

建议新增面向 UI 的状态对象，不直接暴露 SQL 细节：

```text
BatchWorkflowState
- batchId
- batchNo
- productTypeName
- currentQuantity
- currentLocations
- currentStep
- overallStatus
- steps[]
- availableActions[]
- blockingReasons[]
- nextAction
```

步骤对象：

```text
WorkflowStep
- number
- title
- status
- summary
- prerequisiteMessage
- targetPage
- actionText
```

流程状态服务提供：

```text
batchWorkflowState(batchId)
availableWorkflowBatches()
canStartAction(batchId, action)
```

服务职责：

- 从入库、物流单据、库存流水和主数据计算状态；
- 聚合批次当前库存和地点分布；
- 识别调拨、出库、退回和再次出库分支；
- 返回页面需要的下一步文字和跳转目标；
- 不替代业务服务的最终确认权限。

## 6. 界面设计

### 6.1 主窗口流程栏

在现有左侧导航和右侧页面结构上增加统一流程栏：

```text
当前批次：[选择批次 ▼]       流程状态：进行中

01 基础资料  已完成
02 入库      已完成
03 库存安排  不适用
04 出库      当前
05 退回      可选
06 完成      未完成

下一步：进入“出库管理”，选择批次并创建出库单
[去下一步] [查看批次追踪]
```

批次选择器：

- 显示已确认入库和历史批次；
- 显示批次号、产品类型和当前剩余数量；
- 支持按批次号或产品类型查找；
- 选择后在所有页面保持上下文。

### 6.2 业务页面步骤栏

入库页面显示：

```text
步骤 02 / 06：入库
前一步：基础资料
当前操作：创建并确认入库批次
下一步：库存安排
```

调拨页面显示：

```text
步骤 03 / 06：库存安排
前一步：批次已确认入库
可选操作：内部调拨，或直接进入出库
下一步：确认调拨后进入出库
```

出库页面显示：

```text
步骤 04 / 06：出库
前一步：批次已在可用库存库位
当前操作：选择批次、型号和数量
下一步：确认出库
```

退回页面显示：

```text
步骤 05 / 06：退回处理
前一步：存在已确认历史出库
当前可退：型号 / 数量
下一步：确认退回后可再次出库
```

### 6.3 下一步跳转

“去下一步”根据当前批次状态跳转：

| 条件 | 目标页面 | 按钮文字 |
|---|---|---|
| 基础资料缺失 | 基础资料 | 去基础资料 |
| 存在入库草稿 | 入库管理 | 去编辑入库 |
| 已入库且有库存、无调拨要求 | 出库管理 | 去创建出库 |
| 存在调拨草稿 | 调拨管理 | 去确认调拨 |
| 调拨已确认且有库存 | 出库管理 | 去创建出库 |
| 存在可退数量 | 退回管理 | 去登记退回 |
| 退回已确认且仍有库存 | 出库管理 | 去再次出库 |
| 库存为零且无待处理事项 | 批次追踪 | 查看批次追踪 |

跳转后页面自动选择当前批次，必要时选中对应草稿单据。

## 7. 前置校验与提示

UI 层负责禁用明显不可能的操作并提供跳转；服务层负责最终校验。即使绕过 UI，非法单据也不能确认。

| 操作 | 必须满足 |
|---|---|
| 新建入库 | 存在可用产品类型和库存库位 |
| 确认入库 | 产品类型、分类和初始库位启用且有效 |
| 新建调拨 | 存在已确认且有库存的批次 |
| 确认调拨 | 来源和目的地均为库存库位，来源库存足够 |
| 新建出库 | 存在已确认且有库存的批次 |
| 确认出库 | 来源库存足够，型号属于批次产品类型 |
| 新建退回 | 存在可退的历史出库 |
| 确认退回 | 退回型号和数量在可退范围内 |

阻断提示统一包含：

1. 发生了什么；
2. 为什么不能继续；
3. 应该先完成什么；
4. 去前置页面或查看库存的入口。

例如：

```text
无法确认调拨单 T-2026-003。

原因：批次 B-2026-001 在公司仓库可用 120 台，本单请求 150 台。
请减少数量，或先完成其他库存处理。

[返回编辑] [查看库存]
```

## 8. 多批次与历史数据

用户可以在不同批次之间切换，每个批次进度独立：

```text
选择 B-2026-001 -> 处理出库
选择 B-2026-002 -> 处理入库
切回 B-2026-001 -> 处理退回
```

流程状态不依赖访问顺序，不因关闭程序、切换页面或切换批次而丢失。

已停用的主数据仍可用于历史显示，但不能用于新单据确认。历史单据和批次追踪继续显示确认时保存的快照。

## 9. 测试与验收标准

### 9.1 流程状态

- 入库草稿显示入库进行中；
- 已确认入库显示库存安排可选；
- 已确认调拨显示目标库位库存；
- 已确认出库减少批次库存；
- 零库存历史批次保留完整时间线；
- 退回增加库存并允许再次出库；
- 取消单据后状态回到真实库存和单据事实；
- 多批次进度互不影响。

### 9.2 页面行为

- 主窗口显示批次选择器、编号步骤和当前状态；
- 切换批次后流程栏同步；
- “去下一步”跳转到正确页面；
- 前置未完成时新建或确认操作被限制并显示原因；
- 提示包含前置步骤和操作入口；
- 页面自动筛选或预选当前批次；
- 历史单据仍可查看。

### 9.3 回归

- 原有入库、调拨、出库和退回服务测试继续通过；
- 库存数量、流水和冲销规则不改变；
- 报表、批次追踪和库存查询结果不改变；
- 主窗口现有九个导航项继续可用。

## 10. 不在本次范围内

- 自动创建业务单据；
- 自动确认业务单据；
- 强制所有批次必须调拨；
- 将型号拆成独立库存；
- 删除或隐藏历史记录；
- 引入新的返修加工单或型号转换单；
- 通过手工字段保存用户当前步骤。
