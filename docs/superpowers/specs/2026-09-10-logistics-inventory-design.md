# 物流库存管理系统设计

## 1. 目标与范围

在 `E:/Res/Projects/Personally/Qt/LogisticsInventory` 新建单机 Qt 桌面应用，替代石墨表格管理到货、内部调拨、最终出库、批次追踪和库存统计。

第一版使用 Qt 6、C++17、Qt Widgets、CMake 和 SQLite。数据按批次与地点总数管理；FF45、FF60、F45 等是发货用途分类，不是独立实物库存。

## 2. 核心业务规则

- 每个到货批次记录产品类别、物料名称、物料型号、到货时间、到货总数和初始地点。
- 初始地点默认“公司”，也可选择其他启用的库存地点。
- 公司、工厂等属于库存地点；客户、项目现场等属于外部地点。
- 内部调拨在两个库存地点之间移动，不改变批次总剩余。
- 最终出库从库存地点移出系统，减少批次总剩余。
- 同一批次可以分发至多个工厂，并继续从不同工厂出库。
- 一张单据可包含多个批次和多个用途类型明细。
- 每个产品型号可关联多个用途类型，同一用途类型也可供多个型号使用；新增用途类型不修改数据库结构或程序界面。
- 到货仅记录总数量，因此用途类型只用于发货统计，不计算用途类型剩余库存。
- 草稿不影响库存；确认后生成库存流水；已确认单据不可直接编辑。
- 取消已确认单据使用反向流水。存在依赖该库存的后续流转时禁止取消。

## 3. 库存计算

- 批次剩余 = 该批次所有库存地点有效流水之和。
- 地点库存 = 该批次在该地点的有效流水之和。
- 内部调拨生成“发货地负数、目的地正数”两条流水。
- 最终出库只生成发货地负数流水。
- 入库确认在初始地点生成正数流水。
- 确认单据前，按“批次 + 发货地点”校验可用库存。

示例：到货 820，公司调拨工厂A 500、工厂B 320，工厂A出库250、工厂B出库100，则公司0、工厂A 250、工厂B 220、批次剩余470。

## 4. 主数据

- 产品类别：保险箱、网关、呼叫器等。
- 物料型号：所属产品类别、物料名称、型号编码、规格、启用状态。
- 发货用途类型：编码、名称、说明、启用状态。
- 型号用途关联：限定某物料型号允许选择的用途类型。
- 地点：名称、类型（公司/工厂/客户/项目现场/其他）、是否计入库存、启用状态。

禁用资料不再用于新单据，但历史记录必须继续可见。

## 5. 单据与流水模型

### 5.1 入库批次

记录批次号、到货时间、物料型号、到货总数、初始地点、状态和备注。确认入库后，在初始地点写入正数库存流水。

### 5.2 物流单据

物流单据分为内部调拨和最终出库，统一记录单据号、业务时间、发货地点、目的地点、状态和备注。每张单据可有多条明细，每条明细记录批次、用途类型和数量。

### 5.3 库存流水

库存流水记录批次、地点、来源单据、数量变化、业务时间和流水方向：

- 入库：初始地点 `+数量`。
- 内部调拨：发货地点 `-数量`，目的地点 `+数量`。
- 最终出库：发货地点 `-数量`。
- 取消单据：按原流水生成等量反向流水，不删除历史。

库存确认必须在单个 SQLite 事务内完成。任何校验或写入失败时全部回滚。

## 6. 页面结构

应用采用 `QMainWindow`、左侧导航和右侧 `QStackedWidget` 页面区：

1. 工作台：总库存、公司库存、工厂库存、本月入库/出库及最近业务。
2. 入库管理：新增、编辑草稿、确认、查询和查看批次。
3. 调拨管理：库存地点之间移动，支持一单多明细。
4. 出库管理：从库存地点发往外部地点，支持一单多明细。
5. 库存查询：批次库存、地点库存和用途发货统计。
6. 批次追踪：批次概要、流转时间线和当前地点分布。
7. 统计报表：入库、最终出库和地点库存统计，支持 CSV 导出。
8. 基础资料：产品类别、物料型号、用途类型、地点和型号用途关联。

主要功能使用独立页面；新增、编辑和单据明细使用表单对话框。

## 7. 架构与组件

应用采用轻量分层架构：

```text
Qt Widgets 页面/对话框
        ↓
Application Services
        ↓
Repositories
        ↓
SQLite
```

- UI 层负责输入、列表展示、导航和确认提示，不包含库存 SQL 或业务规则。
- Application Service 层负责草稿保存、单据确认、取消、库存校验和 CSV 导出。
- Repository 层封装主数据、批次、物流单据、流水和报表查询。
- SQLite 通过外键、唯一约束、检查约束和索引保护数据完整性。
- 领域对象使用简单 C++ struct 和 value type，不引入 ORM、事件总线或依赖注入框架。
- 使用 `schema_migrations` 顺序执行内置 SQL 迁移。

主要服务：

1. `MasterDataService`：管理类别、物料、用途、地点及型号用途关联。
2. `InboundService`：管理入库草稿、确认和取消。
3. `LogisticsService`：管理调拨与出库草稿、确认和取消。
4. `InventoryQueryService`：提供库存查询和批次追踪。
5. `ReportService`：提供统计查询和 CSV 导出。

## 8. 数据模型

核心表：

- `product_categories`：产品类别。
- `materials`：物料名称、型号编码、规格、所属类别和启用状态。
- `usage_types`：用途编码、名称、说明和启用状态。
- `material_usage_types`：物料型号与用途类型关联。
- `locations`：地点名称、类型、是否计入库存和启用状态。
- `inbound_batches`：批次号、物料、到货数量、初始地点、业务时间、状态和备注。
- `logistics_documents`：调拨或出库单据头。
- `logistics_document_lines`：批次、用途类型和数量。
- `inventory_entries`：不可变库存流水和冲销关系。
- `schema_migrations`：数据库版本。

`inventory_entries` 至少记录批次、地点、来源类型、来源单据、来源明细、数量变化、业务时间、创建时间和 `reversal_of_entry_id`。库存通过全部已过账原流水与反向流水自然求和，不保存可编辑余额字段。

建议索引覆盖 `(batch_id, location_id)`、`(source_type, source_id)`、`business_at` 和 `reversal_of_entry_id`。

## 9. 状态与审计规则

入库批次和物流单据使用统一状态机：

```text
Draft → Confirmed → Cancelled
```

- 草稿可编辑、删除，不影响库存。
- 已确认单据不可编辑或删除。
- 取消通过反向流水完成，不修改或删除原流水。
- 已取消单据不可恢复；需要重做时复制为新草稿。
- 确认和取消仅允许从预期状态执行，重复操作不得重复记账。
- `business_at` 用于业务报表；`created_at`、`confirmed_at`、`cancelled_at` 用于审计。
- 单机第一版不包含登录和权限，不记录操作人。

单据确认时保存物料、用途和地点的关键名称及编码快照。主数据后续改名或禁用不改变历史单据展示。

## 10. 数据约束

- 所有业务数量只允许正整数，流水数量变化必须为非零整数。
- 批次号、单据号、型号编码和用途编码分别唯一。
- 型号用途关联具有联合唯一约束。
- 内部调拨起点与终点不能相同，且均为计入库存的地点。
- 最终出库起点必须为库存地点，终点必须为已启用且不计入库存的外部地点。
- 新单据只能选择已启用主数据；历史记录仍可引用禁用资料。
- `inventory_entries.reversal_of_entry_id` 指向被冲销流水并具有唯一约束，使每条原流水最多冲销一次。
- 启用 SQLite 外键约束：`PRAGMA foreign_keys = ON`。

## 11. 确认与取消流程

### 11.1 确认入库

1. 开启 `BEGIN IMMEDIATE` 写事务。
2. 校验状态为 `Draft`、主数据有效且数量为正整数。
3. 在初始库存地点写入一条正数流水。
4. 保存主数据快照，状态改为 `Confirmed`，记录 `confirmed_at`。
5. 提交事务；任一步失败则全部回滚。

### 11.2 确认调拨或出库

1. 开启 `BEGIN IMMEDIATE` 写事务。
2. 校验状态、地点类型及用途与型号关联。
3. 按“批次 + 发货地点”汇总全部明细数量。
4. 查询事务内实时库存；任一汇总数量超过可用库存则拒绝确认。
5. 调拨每行写入发货地点负流水和目的地点正流水；最终出库每行仅写发货地点负流水。
6. 保存快照并将状态改为 `Confirmed`，然后提交事务。

### 11.3 取消已确认单据

1. 开启 `BEGIN IMMEDIATE` 写事务，校验状态为 `Confirmed`。
2. 读取该单据全部未冲销原流水。
3. 模拟写入等量反向流水。
4. 若任意受影响的“批次 + 地点”库存将小于零，则拒绝取消。
5. 为每条原流水写入反向流水，并通过 `reversal_of_entry_id` 关联原流水。
6. 状态改为 `Cancelled`，记录 `cancelled_at` 后提交事务。

已确认入库也允许按上述规则取消。确认与取消通过状态条件更新和唯一冲销约束保持幂等。

## 12. 界面交互

- 批次选择器仅显示所选发货地点当前库存大于零的批次。
- 禁用主数据不出现在新单据选择项中，历史记录使用确认时快照显示。
- 列表默认按业务时间倒序；第一版使用可滚动表格，不实现服务端分页。
- 输入错误在对话框内定位到具体字段。
- 库存不足时显示批次号、发货地点、可用数量和申请数量。
- 确认和取消前进行二次确认，成功后刷新当前页面和工作台统计。
- CSV 使用 UTF-8 BOM，日期时间格式统一为 `yyyy-MM-dd HH:mm:ss`。

## 13. 错误处理

- 所有确认与取消操作在单个事务中完成，任何校验或写入失败均回滚。
- 数据库异常转换为可操作的用户提示，不向界面暴露 SQL 细节。
- 应用启动时若数据库无法打开或迁移失败，则阻止进入主界面并显示原因。
- 不为框架保证的内部状态增加冗余降级路径；仅在用户输入、数据库和文件导出边界执行校验。

## 14. 测试与验收

- Service 层使用临时 SQLite 数据库进行集成测试，不模拟 Repository。
- Repository 层测试外键、唯一约束、检查约束、查询和报表聚合。
- UI 测试至少覆盖草稿编辑、选择器过滤、确认提示和错误展示。
- 覆盖入库、调拨、最终出库、取消冲销、聚合超发、重复确认、重复取消、事务回滚和主数据禁用。
- 使用第 3 节的 820 件流转示例作为端到端验收基准。

重点验收场景：

1. 入库 820，公司调拨工厂 A 500、工厂 B 320，工厂 A 出库 250、工厂 B 出库 100，最终公司 0、工厂 A 250、工厂 B 220、批次剩余 470。
2. 同一单据中，同一批次按多个用途拆分的合计数量超过库存时确认失败。
3. 调拨到工厂后，工厂已使用部分库存时，若取消原调拨会导致负库存，则取消失败。
4. 任一明细确认失败时，单据状态、流水和库存均保持不变。
5. 重复确认或重复取消不生成重复流水。
6. 主数据禁用或改名后，历史单据仍显示确认时快照。
7. 最终出库只减少发货库存地点数量，不给外部地点增加库存。
8. 应用异常退出后，未提交事务不留下部分流水。

## 15. 第一版范围边界

第一版不包含：

- 库存盘点或手工库存调整；
- 登录、用户、角色和权限；
- 多用户并发和网络同步；
- 用途类型剩余库存；
- 服务端分页；
- 财务金额与成本核算。
